# Domain docs

This repository uses a single-context layout:

- `GLOSSARY.md` at the repository root.
- Architecture decision records under `docs/adr/`.

## Before exploring

Read `GLOSSARY.md` and any ADRs relevant to the area being explored.
If they do not exist, proceed silently. Create domain documentation
lazily through the domain-modeling skill as terminology and decisions
are resolved.

## Vocabulary

Use glossary terms consistently in issues, proposals, hypotheses,
tests, and documentation. Reconsider unfamiliar terminology before
introducing it; record genuine gaps for domain-modeling.

## Decisions

Explicitly identify any proposal that contradicts an existing ADR,
link the decision, and explain why it should be reconsidered.
